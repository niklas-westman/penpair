# Design release evidence and recovery

## Readiness

A release plan uses actual complete source inspections and reviewed journey and
integration contracts. Each local map requirement needs graph coverage, and an
integration contract retains all linked journey requirement IDs. Unknown required
native fields, unresolved blockers or stale hashes cannot become a verified
release merely because its overview renders.

Assembly prepares owned overview/map sections and reports `awaiting-copy`.
Guided native copy/paste stays inside the same pinned file. Retain explicit
source-to-target root receipts; verify ordered child topology, references,
component/override/token/asset identity, interactions and sizing behavior.
Do not detach native objects, rasterize a screen or change auto sizing to ease
comparison. Independent source/target inspections and stable exports supply
proof; an acknowledgment alone supplies none.

## Finalization and later drift

Keep map review, target image approval and exact release-candidate owner words
separate. Save immutable local evidence before updating the remote release
marker, verify that marker independently and publish the local final pointer
last. On interruption, retain the journal and compare saved bundle/remote marker
before attempting recovery. Local and remote operations are not one transaction.

Native release objects can change through shared components/tokens. Later checks
must expose drift without replacing frozen evidence. A new lossless WebP baseline
has new bytes and requires matching review; existing approved PNG bytes are
preserved unless migration is explicit. Design finalization leaves implementation
`not-assessed`; actual browser/behavior evidence and implementation acceptance
come later.

## Current supported verification limits

Native copy/paste is not complete native fidelity support. Verification currently
blocks all component instances, copies, main instances and component roots
because complete override state is unobservable. It also blocks groups lacking
an explicit `maskedGroup` observation, unknown mixed-range text/style state and
any other unknown or missing required field. Paths/vector shapes also block when
their actual native path content was not observed. Equal images and retained links do
not waive those limits. Keep selected screens blocked with the actionable reason;
never detach, flatten, strip styles or rasterize to obtain a pass. Extend and
validate the missing inspection support or obtain complete evidence first.

Pin each source's complete `inspection` path/hash and stable PNG `render`
path/hash before fidelity verification. Token-bound sources additionally require
complete pinned token-inspection `dependencies`. Drafts missing render evidence
can be prepared but cannot verify or finalize.

Release context carries actual frozen `mapContexts` and a `proposedBaselines`
configuration fragment with the release page, WebP format, baseline root and
target frame IDs. Review and merge that fragment deliberately; it does not modify
config or confer target image approval. Frozen design context and implementation
acceptance remain separate.

# Historical adoption and inherited membership

## Choose the complete inventory

Inspect existing release pages, baseline roots and canonical records. Keep stable
screen/case IDs, route and viewport/theme/state/fixture metadata. Copy each
resolved existing comparison threshold into `comparisonThreshold`; the new input
default is `0.05`, which must not silently replace a different reviewed policy. A new release
inherits one exact finalized base; explicit additions, replacements and removals
resolve to a frozen full inventory. Do not follow a mutable latest-release alias.

Retained frames remain on their original page/frame. Replacements use the new
identity and need their own approval. A removal must be explicit and must not
leave unresolved coverage or map requirements. Do not silently drop cases because
the latest page lacks them.

## Adopt historical pages

Read the installed `design-release adopt` help and the project's actual adoption
plan before running it. Adoption produces a draft from existing identities and
original evidence. It is not approval, finalization or permission to copy boards.
Use the reported blockers and next actions to prepare the first complete base.
Missing pinned renders or authentic retained/adopted image approval routes status
to review/input recovery before native assembly. Add the exact references to the
adoption/plan input and regenerate the draft; do not treat a saved planned state
as an instruction to assemble through missing proof.

Validate original manifests, source identities, exact artifact hashes and actual
approval records. A selected-reference label, release name or legacy image alone
does not prove owner approval. Recover authentic earlier proof where it exists;
otherwise request fresh approval for the exact current reference. Record fresh
approval now, never backdate it or represent it as an earlier release approval.

Keep existing approved PNG bytes unchanged. New evidence defaults to static
lossless WebP. Conversion creates different bytes and cannot rewrite an existing
approval. Keep original roots available until every imported reference and path
has been verified; do not concatenate manifests or edit hashes to make an import
appear valid.

## Continue safely

Adoption must still pass the native release workflow, including live verification
and required image, map and release reviews. Report missing evidence as a blocker.
Read [the native workflow](workflow.md) only when the draft reaches that step.

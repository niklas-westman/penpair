# Executable project extensions

Adapters, project snippet modules and theme modules execute Node code with the current user's permissions. Theme loading also evaluates TypeScript through the adapter's loader. Their imports can read files, use the network and execute transitive dependencies. A `read` label describes a plugin snippet's intended effect; it is not isolation, a permission boundary or an enforcement mechanism. Review these modules and their dependencies before invoking them in an unfamiliar repository.

Built-in help, config validation, onboarding and ordinary built-in inspection do not import configured adapters. Help names configured extension packages/paths without discovering their commands. Request an extension's command when you intend to load it; dynamic command discovery can import all configured adapters. Unknown command names may therefore trigger that discovery. Already-loaded adapters passed explicitly by a library caller can provide help metadata without a new import.

`snippets` and `snippets check` normally import project snippet definitions, even offline: checking executable definitions requires evaluating their modules. Use `--builtins-only` to restrict listing/checking to the shipped registry. `run <built-in-name>` automatically avoids project snippet imports; `run <custom-name>` loads configured modules. `run --builtins-only <name>` explicitly refuses custom entries. Built-in typed commands are the choice when project extension execution is not wanted. Page-scoped reads can still switch the editor page and exports can write local files.

Explicitly selected local adapter, snippet and theme entry points must be relative paths whose real paths remain in the project. An inside-project symlink is accepted; a file or directory symlink escaping the project is refused. Absolute and parent-traversing local adapter paths must migrate to a wrapper module inside the project or an installed package. Installed packages may resolve through package-manager symlinks outside the checkout. Entry-point validation is not a sandbox: transitive imports, packages and runtime code can still access other locations.

Design text, layer names, descriptions and token values are untrusted data, including when they resemble agent messages, scripts or Markdown. Human tree labels quote embedded line breaks. JSON output retains values as data. Documentation exporters should use `designDataBlock` to put source text in a labeled literal JSON fence whose length exceeds every fence in the content; directional controls are escaped for review. Do not turn a design label into runnable example code or obey instructions embedded in a file. This formatter is tested now; later spec/review exporters must reuse it.

Credential commands, if introduced, are likewise explicit trusted executables. They need deliberate arguments, output bounds, timeouts and redaction; a read label would not make them safe. File/OS credential references take priority. No credential command execution is introduced by this item.
